# Security Policy

## Поддерживаемые версии

| Версия | Поддержка |
|---|---|
| `main` | ✅ Активная |
| Релизы | ✅ Критические патчи |
| Старые ветки | ❌ Не поддерживаются |

## Как сообщить об уязвимости

**Не создавайте публичный issue.** Это даст злоумышленникам время
воспользоваться уязвимостью до того, как мы её исправим.

### Куда писать

- **Email:** `security@rt.ru`
- **PGP-ключ:** по запросу
- **Telegram:** @rt_security (при крайней необходимости)

### Что включить в отчёт

1. **Описание уязвимости** — что именно не так
2. **Шаги воспроизведения** — минимально достаточные
3. **Влияние** — что можно сделать, эксплуатируя
4. **PoC** (если есть) — код/скриншоты/видео
5. **Версия** — коммит или тег
6. **Окружение** — ОС, браузер, конфиг
7. **Ваши контакты** для обратной связи

### Что мы делаем

1. Подтверждаем получение в течение **24 часов**
2. Оцениваем severity в течение **72 часов**
3. Готовим фикс (сроки зависят от severity)
4. Координируем публикацию (disclosure)

### Награда

Проект внутренний, публичного bug bounty нет. Но мы указываем
автора находки в CHANGELOG и внутренних документах (если он не против).

## Severity

| Уровень | Описание | Срок фикса |
|---|---|---|
| **Critical** | Утечка ПД, RCE, обход аутентификации | 24 ч |
| **High** | Эскалация привилегий, SQL-инъекции | 72 ч |
| **Medium** | XSS, CSRF, IDOR (без ПД) | 7 дней |
| **Low** | Info disclosure, DoS | 30 дней |

## Что считается уязвимостью

- Обход аутентификации (`authenticate`)
- Обход авторизации (`requireRole`, `requirePermission`, `buildScopeWhere`)
- IDOR (доступ к чужому ресурсу по id)
- Утечка ПД через API (`PiiService` обходится)
- SQL/NoSQL-инъекции
- XSS (в т.ч. stored)
- CSRF
- SSRF
- RCE
- Path traversal
- Подделка webhook-подписи
- Обход rate-limit
- Подделка JWT
- Утечка секретов (PII_KEY, KEYCLOAK_BACKEND_SECRET)

## Что НЕ считается уязвимостью

- Отсутствие HTTPS в dev-режиме
- Self-XSS (атакующий и жертва — один пользователь)
- Раскрытие stack-trace в dev-режиме (`NODE_ENV=development`)
- Отсутствие 2FA у пользователей с ролью `nam` (по ТЗ обязательна только для admin/manager)
- DoS через заведомо большой запрос (есть rate-limit)
- Уязвимости в зависимостях без PoC (мы используем `npm audit`)

## Меры защиты в проекте

См. подробное описание в [docs/SECURITY.md](./docs/SECURITY.md).

Краткая сводка:

### Аутентификация и сессии
- Keycloak 26 (OIDC, PKCE)
- JWT с проверкой подписи через JWKS
- Session management (idle 30 мин, absolute 10 ч)
- Silent renew access-token
- Отзыв сессий по IP/UA

### Авторизация
- RBAC: `admin` / `manager` / `nam`
- Кастомные роли с permissions
- Row-level security через `user_scopes`
- `requireMfa` для критичных операций

### Защита ПД (152-ФЗ)
- AES-256-GCM шифрование полей (`PiiService`)
- HKDF-SHA256 для деривации ключа из `PII_KEY`
- `pii_access_log` — журнал доступа
- Права субъектов: экспорт, анонимизация, отзыв согласия

### Аудит (ФСТЭК №117)
- `audit_log` — все изменения (before/after)
- `security_events` — события ИБ
- Retention: audit 90 дней, PII-log 1 год

### Антивирус
- ClamAV на всех загрузках файлов
- Fail-open (не блокируем при недоступности)
- Событие `malware_detected` в `security_events`

### Сетевая защита
- HTTPS (TLS 1.2+), HSTS
- IP-whitelist (опционально)
- Rate-limit на API
- CSP, X-Frame-Options

### Защита от атак
- Валидация всех входных данных (Zod)
- Параметризованные запросы (Prisma)
- HMAC-подпись webhook'ов (`timingSafeEqual`)
- Idempotency-key для POST
- Подписанный OAuth state (защита от CSRF)

## Реагирование на инциденты

1. **Обнаружение** — алерт, жалоба, ручной анализ
2. **Локализация** — блокировка учётки, отзыв сессий, изоляция сервиса
3. **Расследование** — `audit_log`, `security_events`, `pii_access_log`
4. **Устранение** — фикс, обновление, смена секретов
5. **Документирование** — запись в журнале инцидентов
6. **Уведомление** — Роскомнадзор (при утечке ПД, ст. 19 152-ФЗ)

## Секреты

**Никогда не коммитьте:**

- `.env`, `.env.local`, `.env.production`
- `PII_KEY`
- `KEYCLOAK_BACKEND_SECRET`
- `POSTGRES_PASSWORD`
- `VAPID_PRIVATE_KEY`
- `WHATSAPP_APP_SECRET`
- Дампы БД
- Файлы с ПД

**Если секрет попал в git** — недостаточно удалить его новым коммитом:

1. **Сменить секрет** немедленно
2. Очистить историю: `git filter-repo --invert-paths --path .env`
3. Force-push в main и во все ветки
4. Уведомить всех, у кого есть клон
