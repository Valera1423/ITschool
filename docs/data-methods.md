# Методы обработки данных

Документ описывает алгоритмы, используемые в аналитических разделах CRM.

## 1. ABC-анализ

Классификация вузов по вкладу в общую выручку (правило Парето).

### Формулы

- **Доля вуза**: `share_i = value_i / Σvalue × 100%`
- **Кумулятивная доля**: `cumulative_i = Σ(share_1..i)`

### Категории

| Категория | Кумулятивная доля | Интерпретация |
|---|---|---|
| **A** | до 80% | Ключевые партнёры, требуют максимального внимания |
| **B** | 80–95% | Стабильные, требуют планового контроля |
| **C** | 95–100% | Низкий вклад, минимальные усилия |

### Реализация

`backend/src/services/analytics.service.ts` → `AnalyticsService.abcXyz`

---

## 2. XYZ-анализ

Классификация вузов по **стабильности** взаимодействия.

### Формулы

Для каждого вуза за период считаем количество касаний по месяцам.
Далее:
- **Среднее**: `μ = Σx_i / n`
- **Стандартное отклонение**: `σ = √(Σ(x_i − μ)² / n)`
- **Коэффициент вариации**: `CV = σ / μ`

### Категории

| Категория | CV | Интерпретация |
|---|---|---|
| **X** | < 0.33 | Стабильно, легко планировать |
| **Y** | 0.33–0.6 | Средняя стабильность |
| **Z** | ≥ 0.6 | Нестабильно, требует внимания |

### Матрица ABC × XYZ

Комбинация даёт 9 групп:
- **AX** — ключевые надёжные партнёры (приоритет №1)
- **AZ** — важные, но нестабильные (риск)
- **CZ** — низкая ценность + нестабильность (кандидаты на вывод)

## 3. RFM-анализ

Сегментация по трём метрикам: Recency, Frequency, Monetary.

### Метрики

- **R (Recency)** — дней с последнего касания
- **F (Frequency)** — всего касаний
- **M (Monetary)** — сумма договоров

### Шкала (1–5)

**R:**
- 5: < 30 дней
- 4: 30–90 дней
- 3: 90–180 дней
- 2: 180–365 дней
- 1: > 365 дней

**F:**
- 5: ≥ 20
- 4: 10–19
- 3: 5–9
- 2: 2–4
- 1: 0–1

**M:**
- 5: ≥ 1 млн ₽
- 4: 300 тыс – 1 млн ₽
- 3: 100–300 тыс ₽
- 2: 1–100 тыс ₽
- 1: 0

### Сегменты

| Сегмент | Условие | Действие |
|---|---|---|
| **Champions** | R≥4, F≥4, M≥4 | Удержание, апселл |
| **Loyal** | R≥3, F≥3, M≥3 | Программа лояльности |
| **Potential loyalist** | R≥3, M≥4 | Развитие |
| **New** | R≥4, F≤2 | Онбординг |
| **Can't lose** | R≤2, F≥4, M≥4 | Срочное удержание |
| **At risk** | R≤2, M≥3 | Вин-бэк кампания |
| **Lost** | R≤2, F≤2 | Архив |

## 4. LTV (Lifetime Value)

Оценка долгосрочной ценности клиента.

### Формулы

- **LTV**: `Σamount_contracts` (только «Согласован» + «Подписан»)
- **Среднемесячная**: `LTV / months_in_base`
- **Проекция 12 мес**: `avg_monthly × 12`
- **Win rate**: `won / all_contracts × 100%`

### Ограничения

- Расчёт без дисконтирования (приблизительный)
- Используется как оценочная метрика, не для финансовой отчётности

## 5. Когортный анализ

Отслеживание активности групп вузов, объединённых месяцем создания.

### Метод

1. Группируем вузы по месяцу создания: `cohort = YYYY-MM`
2. Для каждой когорты считаем **retention** по месяцам:
   `retention(offset) = active_in_month / cohort_size × 100%`
3. Строим pivot-таблицу: строки — когорты, столбцы — offset (M0, M1, ...)

### Интерпретация

- Плавное снижение → норма
- Резкое падение на 2–3 месяце → проблема онбординга
- Плато → устойчивое ядро

---

## 6. Сравнение периодов

Для каждой метрики считаем:

`change_pct = (current − previous) / previous × 100%`

При `previous = 0`:
- `current > 0` → 100% (рост с нуля)
- `current = 0` → 0%

## 7. Кэширование

Все аналитические запросы кэшируются в Redis на 5–10 минут:

| Метрика | TTL |
|---|---|
| ABC/XYZ | 5 мин |
| RFM | 10 мин |
| LTV | 10 мин |
| Когорты | 10 мин |
| Сравнение периодов | 5 мин |

Инвалидация — при массовых изменениях (`AnalyticsService.invalidateCache`).
